# 单词朗读与发音评测

## 学生端流程

中考、高考、雅思共用“单词朗读”入口。学生主动点按后才加载录音模块并请求麦克风，每次最多录 8 秒。有效录音先成功写入当前账号的本地缓存，再显示回听入口，按需加载评测模块并获取当前会话。

评测前先向受保护的服务端查询配置状态。只有返回 `ready: true`，客户端才把本次录音转换为 16 kHz、单声道、16 位小端 PCM 并提交。未配置时页面明确显示“评测服务待开通”，保留本次朗读记录，不上传音频。

成功结果显示“已评测 · 参考分”，分开呈现发音准确度与综合参考分，单位为 `/ 100`，不称作“正确率”。准确度缺失时显示“暂无可靠分数”，不会用综合分代替。真实数值 `0` 可以显示；没有结果、拒评、超时或额度不足时不显示虚构的 0 分。

页面只显示**最近一次有效录音**关联的结果。较早高分保留在历史证据中，不覆盖新录音的待验证状态。看着单词朗读属于辅助练习，不能推导独立回忆、通过、单词掌握或通关。

“查询本次结果”只对最近一条已保存录音做认证 GET 查询，不重新上传音频、不重新发起讯飞评测。超时或重新打开页面后，可恢复服务端已有结果。若该次录音从未提交评测，查询不会补发；需要服务就绪后重新录制。本地保存失败不会触发评测提交。

当前只支持单个英文词条。短语、数字及不支持的字符仍可录音回听，并明确提示暂不自动打分。拼写和中文选英文题在答案揭晓前隐藏入口；搭配题显示时不把短语录音记到宿主单词。

## 音频与隐私边界

页面提示：“录音用于讯飞发音评测；聚光只保存练习记录和结果，录音仅供本次回听。”

原录音 Blob 仅留在当前页面内存，不放入 localStorage、学习进度 JSON 或 Supabase 音频存储。评测服务把 PCM 转发给讯飞，不把原音频写入数据库、日志或评测结果。这描述聚光自身的实现，不承诺第三方服务的留存政策。

换词、离开练习页、切换账号、退出登录、页面关闭或进入后台时，停止录音、释放播放地址并取消客户端评测请求。已经到达服务端的评测可能继续完成，可稍后查询同一记录的已有结果。离开卡片或刷新后不能再回听旧录音，练习元数据与参考分仍随账号保存、同步。

示范播放会中断正在进行的录音；开始录音会停止示范与连杀语音。评测期间可以回听或继续学习。麦克风或评测不可用不强制阻塞答题。

## 数据与账号归属

原始录音证据保持不可变，评测结果另存于 `oralOutput.assessments`：

```js
{
  version: 1,
  attempts: {
    oral_example: {
      id: "oral_example",
      at: "2026-11-20T08:00:00.000Z",
      durationMs: 1800,
      mimeType: "audio/webm;codecs=opus",
      status: "recorded",
      assisted: true,
      referencePlayed: false,
      audioCheck: "signal_detected"
    }
  },
  assessments: {
    ise_example: {
      id: "ise_example",
      attemptId: "oral_example",
      owner: "11111111-1111-4111-8111-111111111111",
      cardKey: "zhongkao|0::apple",
      word: "apple",
      provider: "xfyun-ise",
      at: "2026-11-20T08:00:05.000Z",
      scale: 100,
      accuracyScore: 84.5,
      totalScore: 81,
      status: "assessed",
      modelVersion: "xfyun-ise-en-v1"
    }
  }
}
```

示例身份与分数均为虚构测试数据。

- `assisted: true` 表示看词朗读，不是独立回忆测验。
- `referencePlayed` 只记录本卡片示范语音实际开始播放，不声称学生听到、听懂或跟读正确。
- `audioCheck` 只区分检测到音量信号与无法检查，不证明录到人声、英语或正确单词。
- 少于 350 毫秒、空文件，以及可可靠检测的持续静音，不作为有效练习保存。
- `accuracyScore`、`totalScore` 可以各自为 `null`，但至少一项必须是 0–100 的有限数值。拒评、非零异常标记、错误模型或分制不会作为有效分数写入。
- 同 ID 的录音和评测都只追加一次，不能用重试覆盖原记录，也不截断历史。

每次操作捕获账号 ID、录音 ID、卡片 key、目标单词和页面代次。异步工作与落盘前都重新核对上下文，新账号或新卡片不能接收旧结果。服务端以 Bearer 会话认证确定 owner，浏览器不通过请求体声明 owner；返回结果也必须匹配捕获的身份和目标。

客户端先确认本地持久化成功，再更新内存并请求现有自动同步。同步按 ID 合并完整的 attempts 和 assessments，保留原始证据、旧客户端未识别的字段以及待上传工作。朗读和分数都不增加 `studiedCount`、积分、连杀、SRS、拼写成绩、词义正确次数或通关状态。

页面内存中的进度同时固定所属账号，本地写入显式使用该账号。若账号缓存先切换、旧账号的同步确认随后才到达，同步层拒绝接纳，页面保存层也拒绝写入新账号。旧账号的缓存和待同步队列仍保留，不能把整份旧进度复制给下一位学生。

## 服务端配置与调用边界

入口：`https://cmainasvlfdynidabunp.supabase.co/functions/v1/word-pronunciation`。

客户端仅使用已有公开浏览器 key 和当前学生会话。讯飞的 `APPID`、`APIKey`、`APISecret` 只允许配置在服务端，禁止放入前端、进度记录或日志。实现位于 `grok/supabase/functions/word-pronunciation/`，数据库迁移为 `grok/supabase/pronunciation_assessment.sql`。

| 请求 | 含义 | 是否提交讯飞评测 |
| --- | --- | --- |
| GET，无 attemptId | 返回 `ready` 配置状态与本应用限额 | 否 |
| GET，附 attemptId | 返回本人该次录音的已有结果或处理中状态 | 否 |
| POST，目标词及 PCM | 持久化请求身份后提交一次真实评测 | 仅首次获准请求 |

客户端不会在失败后自动重试 POST。服务端对账号、录音 ID 和目标做持久化幂等控制，超时或丢失响应不能通过重复请求重复调用供应商。学生或公开角色没有直接写入结果表的权限。

音频转换最长等待 8 秒，状态检查最长 8 秒，评测或结果查询最长 25 秒；模块加载与会话读取也有独立上限。网络错误、不可解码录音、拒评、额度不足、服务异常或存储失败均保留原始朗读证据，并显示下一步。

## 费用与开通状态

浏览器录音、回听和查询已有结果不发起新的讯飞评测。真实评分使用讯飞英语语音评测服务，不采用普通语音识别文本是否一致来冒充发音准确度，也不让聊天模型主观编分。

本应用服务端限制为滚动 24 小时全站最多 400 次、每位学生最多 40 次。10 名学生按每人 40 次计算为 400 次。新录音提交会占用新的评测请求，查询已有结果不会新增供应商调用。应用限额是本项目的保护边界，**不代表讯飞账号已经有相同数量的免费权益**。

讯飞官方接口说明：https://www.xfyun.cn/doc/Ise/IseAPI.html

只有认证 GET 实际返回 `ready: true` 才表示所需服务端配置齐备。代码部署完成不等于讯飞账号已开通，也不等于已经充值。实际免费额度、有效期、并发、计费与超额规则以用户的讯飞控制台为准。缺少密钥时返回未就绪；本实现不购买套餐、不充值、不自动切换收费供应商。

- `tests/oral-output.test.js`：录音生命周期、权限与超时、空/短/静音音频、8 秒上限、取消和麦克风释放。
- `tests/oral-assessment.test.js`：PCM、低通重采样、Web Audio 生命周期、状态查询、超时与取消、归属绑定、零分/缺失值、不可变结果和页面集成。
- `tests/ise-backend.test.js`：请求校验、讯飞协议与拒评、认证、限额、持久化幂等与结果恢复。
- `tests/oral-output-sync.test.js`：账号隔离、跨设备追加、旧字段兼容、无历史裁剪、断网恢复及丢失 ACK 后不重复。
- `tests/oral-output-browser.test.js`：真实 Chromium 页面、375px 布局、按需加载、模拟录音评测、回听、查询和换词/退出/换账号的异步归属。
- `tests/grok-sw.test.js`：缓存版本和私有评测请求不进入公共离线缓存。

测试使用虚构账号、合成音频和模拟评测响应，不使用学生音频，不消费讯飞额度。模拟结果验证数据与交互边界，不能证明真实声学评分准确度，也不代表已在真实 iPhone、Android 或微信内置浏览器完成硬件兼容性验证。发布仍须通过 `node tools/verify-learning-contracts.js` 完整检查。
