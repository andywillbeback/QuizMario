# 登录与首页启动修复

## 已确认的问题

基线为 `d87066221586925c3fd4125725e0eb2905f3d859`。

1. 页面缓存采用 network-first。即使登录页或首页已缓存，仍要先等网络完整响应，最长约六秒后才回退缓存。
2. 登录页的装饰光球在认证处理器前异步启动，持续绘制，输入及页面隐藏时也不暂停。
3. 首页将认证确认、学习内容下载和本账号进度恢复都显示为“正在确认登录”。认证一旦成功就取消总启动计时器，后续资源卡住时可能没有退出该等待状态的明确操作。
4. 入口和同步模块各自读取一次会话；云端进度读取要等首页全部脚本执行完才开始。

首页原始外部脚本合计 3,854,473 字节，其中 `words.js` 和 `exam-tracks.js` 合计 3,208,845 字节。它们的下载与执行在学习首页就绪的关键路径上。这是源文件大小，不是经过压缩的实际传输量，也不是用户网络的耗时测量。

登录页及首页没有加载 Three.js、单词宇宙渲染器或宇宙 iframe。首页的 `universe-progress.js` 为 8,747 字节，提供学习证据和通关记录；移除宇宙不能消除上述大词库负担。

## 本次改动

- 已缓存的公开页面给网络 350 ms 的优先窗口，之后可先返回缓存。后台刷新保留六秒上限，缓存写入纳入 Service Worker 生命周期。认证请求、学习数据与登录回调不经过该缓存。
- 认证依赖在 HTML 前部尽早下载，所有外部脚本按依赖顺序 `defer` 执行。首页装饰放到功能脚本之后。
- 登录光球在认证事件处理器就绪后、空闲时启动；移动设备使用较低绘制预算，输入、隐藏及离屏时暂停，减少动态效果设置得到尊重。
- 入口与同步模块共享经过验证且有期限的会话结果。验证后提前读取本账号进度，与其余资源准备重叠；同步只消费一次、且必须匹配同一个账号。
- 启动提示区分账号验证、内容准备、进度读取。加载过慢或临时连接错误提供刷新操作；只展示中性提示，不能凭本地登录提示或其他账号缓存打开学习界面。

## 数据与范围

本次保持原词库、单词宇宙、学习规则及其布局；未改变账号服务地址。已验证且明确属于当前账号的本机缓存仍可快速进入学习，新学习记录仍先持久保存，云端基线协调完成后才上传。首次设备仍需核对本账号云端进度，认证失败、账号切换及迟到回调不得显示其他账号记录。

本补丁不包含完整词库拆包，因此不会消除首次访问时的全部词库下载量。此前约 65% / 79% 的资源体积减少属于另一组尚待发布的词库与宇宙优化，不能作为本补丁收益。

## 验证与发布

新增回归覆盖已缓存页面的慢网络、后台刷新生命周期、登录动画暂停、共享会话与进度读取、启动超时和账号切换。原有学习数据验证不变。

发布前必须运行 `node tools/verify-learning-contracts.js`。PR 验证执行同一套完整检查；合并后 Pages 仍由成功的 `verify` 作业解锁部署。浏览器无法启动属于验证阻塞，不能视为通过或跳过。
